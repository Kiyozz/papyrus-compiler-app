# project

2026-08-30, whole-project migration from Radix UI to Base UI. All 19 radix
wrappers migrated; `radix-ui` removed from the dependency tree.

## Dependency swap

- `pnpm add -D @base-ui/react` -> `@base-ui/react@1.7.0`.
- `pnpm remove radix-ui` (was `radix-ui@^1.6.7`). No radix package remains, and
  `pnpm-lock.yaml` was regenerated by pnpm itself.
- `components.json` style flipped from `radix-maia` to `base-maia`, so future
  `shadcn add` calls deliver Base UI variants with this project's preset
  (`b7VDeYNIw`: maia / taupe / figtree / lucide).

## How it was done

For every wrapper, both goldens were generated by the shadcn CLI itself
(`shadcn add <component> --overwrite`, once with the style set to `radix-maia`
and once with `base-maia`) so aliases and icon placeholders came out resolved
the way this project resolves them. Both goldens were then formatted with the
project's `oxfmt` config, which reduced each wrapper's real diff against its
radix golden to a handful of lines, and each file was produced by
`git merge-file <user> <radix-golden> <base-golden>`. 12 of 18 merges came out
clean; the rest were resolved by hand (mostly the license header + import
block, plus dialog, sheet, select and button which carried real
customizations). `form.tsx` has no maia golden at all and was transformed by
hand.

Every file was then swept with `grep -n "radix-ui\|@radix-ui\|IconPlaceholder"`,
including the ones that merged clean.

## Shared change

`src/renderer/lib/utils.ts` — `cn` gained two overloads. Base UI types
`className` as `string | ((state) => string | undefined)`, so a wrapper merging
its own classes with an incoming one has to preserve that shape. `cn` returns a
plain string unless one of its inputs is a function, in which case it returns a
function of the state. Without this, ~60 of the type errors after the swap were
`cn(className)` calls. It is the only change outside the wrappers and their
consumers.

## App-code sweep

`asChild` -> `render` (12 call sites): `app-sidebar.tsx`,
`dialog-compilation-logs.tsx` (x3), `dialog-documentation.tsx` (x2),
`dialog-recent-files.tsx`, `groups-menu.tsx`, `groups-list-item-menu.tsx`,
`script-line.tsx`, `settings-page.tsx` (x2).

Other call-site breaks found by the sweep:

- Tooltip: `delayDuration` has no per-root equivalent in Base UI — it moved
  onto local `<TooltipProvider delay={...}>` wrappers in
  `dialog-compilation-logs.tsx`, `script-line.tsx` and
  `settings-game-section.tsx` (x2). `disableHoverableContent` renamed to
  `disableHoverablePopup` (`settings-page.tsx` x2, and the two above).
- `dialog-setup.tsx`: `onEscapeKeyDown` / `onInteractOutside` removed — Base UI
  has no per-part handlers, and the controlled root's `onOpenChange` already
  blocked both while `isBlocking`.
- `dialog-compilation-logs.tsx`: `color="error"` dropped from a `Button` (an
  inert HTML attribute Base UI's Button omits from its props).
- The three dialog wrappers that forwarded `children` into a trigger now type
  that prop as `ReactElement` rather than `PropsWithChildren`.

Runtime finding, fixed after the first launch: `app-sidebar.tsx` wrapped its
footer `<SidebarMenuItem>` (an `<li>`) in the dialog, so the trigger's props
landed on the list item rather than on the button inside it. Radix accepted it
silently; Base UI's `DialogTrigger` warns (`nativeButton`). The dialog now wraps
the `<SidebarMenuButton>`. Among the parts Base UI checks this way
(`DialogTrigger`, `DialogClose`, `MenuTrigger`, `MenuItem`, `SelectTrigger`...)
this was the only offending call site; `TooltipTrigger` does not enforce it,
which is why `SidebarMenuButton render={<Link />}` is fine.

Second runtime report, NOT caused by this migration: the group dialog pushed
its footer buttons out of the rounded box. Reproduced both DOM shapes (Radix
and Base UI) side by side against the built stylesheet — identical to the
pixel (popup 490px, footer overflowing by 54px in both). The cause is
`dialog-group.tsx`: the script list was a fixed `h-96` inside a form whose
`h-full` resolved against nothing, so the form grew past the popup's
`max-height`. Fixed by making the form own the height budget
(`flex min-h-0 flex-1 flex-col`) and the list elastic (`min-h-0 flex-1`),
verified against the empty / one-script / thirty-script cases.
`dialog-recent-files.tsx` uses the same `h-96` but is fine, and that confirms
the diagnosis: there the scroll area is a direct child of the popup, which is
a `flex flex-col` with a real `max-height`, so it just shrinks when the limit
is reached. The group dialog's form sat in between and broke that chain.

`src/renderer/locales/*/messages.po` changed only in their `#:` reference
comments (lingui extract during the build); no msgid or translation moved.
